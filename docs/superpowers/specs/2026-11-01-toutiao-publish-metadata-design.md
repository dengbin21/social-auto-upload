# 头条号视频发布元数据与提交确认修复设计

## 目标

防止后续头条号视频发布出现以下问题：

- 将上一条视频的简介、标签等元数据误用于当前视频。
- 未选择目标分类而由平台使用默认分类。
- 表单字段写入失败仍继续提交。
- 仅因“发布”按钮已点击就误报发布成功。

本次不重新发布、编辑或删除 `zhaosan` 的任何平台作品。

## 已确认的根因

1. `zhaosan` 的头条发布命令手工传入了《江雪》元数据，包括“千山鸟飞绝”“曹操《江雪》”和 `zhaosan,古诗词,唐诗`。而项目来源卡 `zhaosan/hook-card.json` 的主题是《庄子·齐物论》“朝三暮四”及框架效应。错误发生在命令输入，不是头条号自动修改内容。
2. 当前头条 CLI 没有 `--category` 参数，上传器也没有分类选择及回读，因此分类保留平台默认值或当前表单值。
3. 当前提交确认只等待 URL 离开上传页或页面文案出现成功词。页面停留在上传页、没有可识别成功信号时，无法区分平台校验阻止、网络状态或异步提交；此前多次执行又放大了重复提交风险。
4. `sau` 入口脚本实际导入 `/Users/robin/tools/social-auto-upload`，修复必须在该目录生效。它当前不是 Git 工作树，因此无法创建 Git commit；该限制会在交付中明确记录。

## 方案

### 发布清单

增加一份可被 CLI 读取的发布清单 JSON。清单是某一个视频的唯一元数据来源，至少包括：

- `video_file`：绝对视频路径或相对清单文件的路径。
- `title`
- `description`
- `tags`
- `category`
- `thumbnail_file`（可选）
- `generate_article`

头条上传增加 `--metadata <json>`。使用该参数时，视频、标题、简介、话题、分类、封面和生成图文选项都从清单读取；任何同名 CLI 参数将被拒绝，避免两个来源互相覆盖。

保留当前的逐参数调用模式以兼容已有用户，但 `--category` 改为必填。逐参数模式不提供视频主题自动推断，调用方必须显式提供正确元数据。

本次会为 `zhaosan` 创建正确的未来复用清单，但不会调用上传命令。

### 分类发现和填写

头条号分类不是写死常量。上传器在已登录发布页面读取当前可选分类；指定分类不在页面选项中时，在上传和提交之前失败并输出实际可选项。

分类选择基于带有“分类”字段标签的局部表单容器，而不是全局相同样式的下拉控件。选择后必须回读控件文本并与请求分类完全相等，否则停止。

由于分类的实时 DOM 尚未记录，先通过无上传、无提交的已登录页面探测确定选择器和选项文本；该探测不得选择任何文件、填写任何字段或点击发布。

### 表单写入与校验

抽出独立方法填入标题、简介、话题和分类。标题、简介、分类均读回其控件实际值。话题以真实标签 chip 数与实际文本确认。

任一必填字段找不到、无法写入或读回值不匹配时抛出错误。不会再以“跳过”形式继续发布。

### 提交确认和安全性

在点击发布前检查：视频上传完成、标题/简介/话题/分类的读回值、封面（若指定）、AI 声明。

点击后每轮检查以下状态：

1. 明确成功提示或跳转到内容管理页。
2. 页面内显式校验或失败提示，错误直接带出。
3. 已点击但仍在上传页且没有成功信号，超时后返回“提交结果未知”，不报告成功。

未知结果不自动重试点击发布，避免重复作品。命令退出失败，使调用方必须先在内容管理页核实，再决定是否再次发布。

### 范围外

- 不处理 `zhaosan` 已有作品的修改、补发或删除。
- 不修改其他平台上传器。
- 不把头条实时分类名称写死为常量。
- 不改变支付宝相关代码。

## 测试与验证

自动化测试覆盖：

- CLI：逐参数模式缺少分类被 argparse 拒绝；清单模式加载全部字段并拒绝与直接参数混用；错误清单路径或字段失败。
- 表单：简介、分类写入后必须读回；分类不存在、选择后读回不一致时失败；话题验证实际写入结果。
- 提交：明确成功正常返回；页面校验错误失败；超时仅报告结果未知且没有第二次点击。
- 回归：头条相关测试、完整 Python 测试套件以及 CLI 帮助输出。

在有有效登录态的情况下，做一次只读发布页探测验证分类控件选择器和实际选项。该步骤不上传文件、不写表单、不点发布。
